# ภาพรวมโปรเจกต์: Where Winds Meet — แปลไทยใหม่ทั้งเกม

เอกสารนี้อธิบายตั้งแต่ต้นจนจบสำหรับนักพัฒนา ได้แก่ เกมเก็บข้อความอย่างไร มอดของเราแทรกเข้าไปตรงไหน
ข้อมูลไหลผ่านเครื่องมือแต่ละตัวอย่างไร และทำไมถึงออกแบบแบบนี้

---

## 1. ภาพรวมในหนึ่งรูป

```
            เกม (Steam)                                   โปรเจกต์ของเรา
┌──────────────────────────────────┐         ┌─────────────────────────────────────────────┐
│ Package/HD/oversea/locale/        │  build  │ backup/original/   ← ต้นฉบับที่สำรองไว้       │
│   translate_words_map_zh_cn       │ ──────► │ work/wwm.db        ← ฐานข้อมูลคำแปล (SQLite) │
│   translate_words_map_en          │  _db    │ glossary/          ← ชื่อเฉพาะ / ศัพท์        │
│   translate_words_map_th   ◄──────┼──┐      │ work/queue/NNNN.tsv      ← ก้อนงานรอแปล       │
│   translate_words_map_th_diff ◄───┼──┤      │ work/queue/NNNN.out.tsv  ← ผลแปล              │
│ LocalData/Patch/HD/.../*_diff     │  │      └───────────────┬─────────────────────────────┘
└──────────────────────────────────┘  │                      │ build_mod.bat
                                      └── copy ◄── wwmloc patch (สร้างไฟล์ไทยใหม่จาก backup + DB)
```

แนวคิดหลักคือ เราไม่ได้แก้โค้ดเกมเลย เราแค่สร้างไฟล์ภาษาไทยของเกม (`translate_words_map_th*`)
ขึ้นมาใหม่ทั้งไฟล์ ให้โครงสร้างเหมือนต้นฉบับทุกไบต์ ยกเว้นตัวข้อความ แล้ววางทับไฟล์เดิม

## 2. เกมเก็บข้อความอย่างไร

### 2.1 ไฟล์ภาษา

ทุกภาษาอยู่ในโฟลเดอร์ `Package/HD/oversea/locale/` ภาษาละไฟล์ เช่น `translate_words_map_zh_cn`, `_en` และ `_th`
แต่ละไฟล์คือ **ตาราง key → ข้อความ** โดย key เป็นไบต์ 8 ตัว (เขียนเป็น hex 16 ตัวอักษร)
และทุกภาษาใช้ key ชุดเดียวกัน ดังนั้น key เดียวกันใน `zh_cn` กับ `th` คือข้อความเดียวกัน
ในเกมมีราว **1.12 ล้าน key**

### 2.2 โครงสร้างไฟล์ (reverse-engineer เอง อยู่ใน `tools/wwmloc.py`)

```
Container (little-endian)
  u32 magic = 0xDEADBEEF | u32 version (=1) | u32 n_blocks
  u32 offsets[n_blocks + 1]        ← ตำแหน่งแต่ละบล็อก (นับจากต้นส่วน data)
  data: แต่ละบล็อก = u8 type (4 = zstd, 0 = ไม่บีบอัด) | u32 comp_size | u32 raw_size | payload

Text block (หลัง zstd decompress) = hash table แบบ open addressing
  u64 capacity | u64 used | u32 TEXT_SIG (0x595896DC) | u32 ?
  u8  ctrl[capacity + 16]          ← byte ควบคุม (บิตบนตั้ง = ช่องว่าง) แล้ว pad ให้ลง 8
  slot[capacity] { u8 key[8] | u32 rel_off | u32 byte_len }
  สตริง UTF-8 ต่อกัน (สตริงที่เหมือนกันใช้ร่วมกันได้)
```

- **บล็อก 0** เป็น index ของเกม ลายเซ็นไม่ใช่ TEXT_SIG เราเก็บไว้ไม่แตะ
- **ตอนแพตช์** เราไม่เพิ่มหรือลบ key จึงใช้ hash table เดิม (ctrl + ลำดับ key) ได้ทั้งหมด
  และเขียนใหม่แค่ส่วนสตริงกับ offset/length ของแต่ละ slot แล้วบีบอัด zstd กลับ
- **ทดสอบแล้ว:** ถ้าเอาไฟล์ไป rebuild โดยไม่เปลี่ยนข้อความ จะได้ไบต์ตรงกับต้นฉบับทุกไบต์ (`wwmloc.py verify`)

### 2.3 ไฟล์ `_diff` และการซ้อนชั้น

นอกจากไฟล์หลัก ยังมีไฟล์ `_diff` ที่ใช้ override บาง key

```
ข้อความที่เกมแสดง = ไฟล์หลัก (Package/…/translate_words_map_th)
               ← ทับด้วย Package/…/translate_words_map_th_diff
               ← ทับด้วย LocalData/Patch/HD/…/translate_words_map_th_diff (ตัวอัปเดตเกมเขียน)
```

- **ค่า `0xFF` ใน `_diff`** เป็น tombstone แปลว่า "ไม่ override ให้ใช้ค่าจากชั้นล่าง" เราจึงข้าม key นี้ ไม่แปลทับ
- **ตั้งแต่อัปเดต 2026-11:** ภาษาไทยแบ่งเป็นสองไฟล์ใน Package คือไฟล์หลัก (~718k key) และ `_diff` (~467k key)
  `build_mod.bat` จึงแพตช์ทั้งสองไฟล์
- **ไฟล์ใน `LocalData/Patch`:** ตัว patcher ของเกมจะ **เขียนทับคืนเป็นของเดิม** ทุกครั้งที่เปิดเกม
  - **Steam (ทดสอบ 2026-11-19):** มี `_diff` ชั้นนี้ด้วย เป็นไฟล์ตัวเดียวกับของ Lite (467k key ครบทุก key ของ `_diff`)
    เกมจึง **ไม่ได้ใช้** `_diff` ใน Package เลย ~390k key (~40% ของข้อความ รวมคัตซีนบางฉาก) เป็นไทยเดิมเสมอ
    - ไฟล์ม็อดแบบ read-only: patcher ในเกมขึ้น "fetch locale files failed ... deleting ...\locale" เข้าเกมไม่ได้
    - ไฟล์ม็อดแบบไม่ read-only: patcher เขียนต้นฉบับทับตอนเปิดเกม (ก่อนเกมอ่านข้อความ)
    - ลบไฟล์ทิ้ง: patcher โหลดต้นฉบับกลับมา
    - สรุป: บน Steam ม็อดแก้แค่ `Package` ได้ประมาณ 60% (สคริปต์ข้าม `LocalData` บน Steam ใน `Get-Slots`)
    - ไม่ทำ: แก้ฐานข้อมูลของ patcher (`LocalData/Patch/Patch.mpkdb`) ให้ยอมรับไฟล์ม็อด = หลบระบบตรวจไฟล์ของเกม เสี่ยงแบน
    - จุดสังเกตใน `_diff` เท่านั้น: 家业 (เมนูบ้าน) เดิม "บ้านช่อง" ม็อด "คฤหาสน์" (Steam จะเห็น "บ้านช่อง" เสมอ)
- **ตัวติดตั้งของเกมเอง (standalone, beta):** ข้อมูลข้างล่างมาจากแบบ **Lite** (`wwm_lite`) เท่านั้น
  แบบ **Standard** (`wwm_standard`) ยังไม่ได้ทดสอบ ไม่รู้ว่าไฟล์ภาษาอยู่ที่ไหน
  - Lite: ไฟล์ภาษาไทยทั้งหมดอยู่ใน `LocalData/Patch` (`Package/HD/oversea/locale` ไม่มีไฟล์ภาษา)
    (ไฟล์หลักตัวเดียวกับ Package ของ Steam + `_diff` ตัวเดียวกับ LocalData ของ Steam)
  - build: `build_mod.bat` สร้าง `work/build/sa_translate_words_map_th_diff` จาก `backup/original/LocalData`
    แล้ว `make_release.py` ใส่ค่า `sa_orig_*` / `sa_mod_*` ใน manifest
  - ทดสอบแล้ว (2026-11-17): ถ้าไฟล์ม็อดเป็น **read-only** patcher จะโหลดไฟล์ใหม่เป็น `.tmp`
    แทนที่ไม่ได้ แล้วข้ามไปเงียบ ๆ (ไม่ error) ม็อดจึงอยู่รอด
  - ตอนเกมอัปเดต: `play.bat` เห็น `LocalData/Patch/patching_version.txt` เปลี่ยน
    -> คืนต้นฉบับ (ปลด read-only) ให้ patcher อัปเดตไฟล์ภาษา -> รอบถัดไปติดตั้งม็อดใหม่
  - ภาษาของหน้าต่าง launcher กับภาษาเกมแยกกัน (`LocalData/patch_conf.json`: `launcher_language` / `language`, `lang_types`)

### 2.4 รหัสพิเศษในข้อความ

ตัวข้อความไม่ใช่ข้อความล้วน แต่มีโค้ดที่เกมใช้ render ฝังอยู่ ซึ่งต้องคงไว้ให้เป๊ะ

| รหัส | ความหมาย |
|---|---|
| `#Y…#E`, `#8c5823…#E` | สีข้อความ (ตัวอักษรสี หรือ hex 6 หลัก) |
| `{0}`, `{数量1}`, `%s`, `%d`, `$N` | ตัวแทนค่าที่เกมใส่ทีหลัง ลำดับ `%s/%d` ต้องเหมือนเดิม |
| `<LINK …>`, `<IMAGE …>` | ลิงก์และรูปในข้อความ |
| `\n` | ขึ้นบรรทัด จำนวนต้องเท่าต้นฉบับ |
| `\|` | แยกคำสำหรับผู้เล่นชาย/หญิง |
| `[#201]` | อีโมตเป็นตัวเลข คงไว้ (ส่วน `[#送花]` เป็นข้อความธรรมดา แปลได้) |

## 3. ทำไมต้องแปลใหม่

คำแปลไทยทางการของเกมมีปัญหาหลายแบบ:
- แปลตรงตัวจนอ่านไม่รู้เรื่อง (เช่น ชื่อผู้เล่นถูกแปลความหมาย หรือ "3000 หมื่นคน")
- ข้อความจีนเดียวกันแปลไม่เหมือนกัน (ประมาณ **122k ข้อความ** มีคำแปลไทยทางการมากกว่า 1 แบบ)
- ชื่อเฉพาะเรียกปนกันหลายแบบ

เป้าหมายของเราคือแปลใหม่จาก **ภาษาจีนต้นฉบับ** ให้ลื่นและสม่ำเสมอทั้งเกม

## 4. ฐานข้อมูล `work/wwm.db`

`tools/build_db.py` อ่านไฟล์ภาษาทุกชั้น แล้วยุบให้เหลือ **ข้อความจีนที่ไม่ซ้ำกัน** เพราะ key จำนวนมากใช้ข้อความเดียวกัน
แปลครั้งเดียวจึงได้หลาย key: 1.12M key ยุบเหลือ ~480k ข้อความ

| ตาราง | เนื้อหา |
|---|---|
| `sources` | 1 แถวต่อข้อความจีน 1 แบบ: `zh`, `en`, `th_old` (คำแปลทางการที่พบมากสุด), `n_keys`, `category`, `priority`, `th_new` (คำแปลของเรา), `status`, `note` |
| `entries` | 1 แถวต่อ key ของเกม: `key → src_id` และบอกว่ามาจากไฟล์หลักหรือ `_diff` |
| `meta` | เวอร์ชันเกม, hash ของไฟล์ต้นฉบับ, ประวัติการอัปเดต |

**category** มี `ui_short` (ปุ่ม/เมนู), `label` (ชื่อไอเทม/สกิล), `dialogue`, `description`, `long_text` (จดหมาย/คัมภีร์) และ `empty`
แต่ละประเภทมีกฎการแปลต่างกัน และใช้จัดลำดับงาน

**status** มี `todo` → `queued` (อยู่ในก้อนงาน) → `done` และ `needs_fix` (ตรวจไม่ผ่าน) กับ `unused` (เกมไม่ใช้แล้ว)

## 5. ไปป์ไลน์การแปล

```
build_db.py ──► wwm.db ──► translate.py chunks ──► work/queue/NNNN.tsv
                                                       │
                       (แปล: ในแชท / Subagent / Claude API batch)
                                                       ▼
                                             work/queue/NNNN.out.tsv
                                                       │ translate.py check (validator)
                                                       ▼
build_mod.bat: import-queue ──► export-tsv ──► wwmloc patch ──► copy ลงเกม
```

### 5.1 แบ่งเป็นก้อน (`translate.py chunks`)

- ดึงข้อความ `todo` เรียงตาม priority ซึ่งคิดจากจำนวน key หรือความถี่ที่ผู้เล่นเห็น แล้วตัดเป็นก้อน
  ขนาดก้อนแล้วแต่ประเภท: long_text 20, description 400, UI/label 300
- **`--new`:** ดึงเฉพาะข้อความที่มาจากอัปเดตเกมล่าสุด
- **ข้อมูลในแต่ละก้อน:** `id, zh, en, th_old, terms` โดย terms คือศัพท์จาก glossary ที่เจอในข้อความนั้น
- **`pick`** จองก้อนด้วยไฟล์ `NNNN.inchat` เพื่อไม่ให้สองฝั่งแปลก้อนเดียวกันซ้ำ

### 5.2 การแปล

ใช้มาสามวิธี:
1. **แปลในแชท:** Claude แปลเองทีละก้อน
2. **Subagent:** สั่ง agent ทีละ 10 ตัว ตัวละ 1 ก้อน ทุกตัวอ่านคำสั่งจาก `docs/AGENT_CHUNK_TASK.md`
   พอตัวไหนเสร็จ เราตรวจแล้วส่งตัวใหม่ไปแปลก้อนถัดไป ใช้ token ราว 120–190k ต่อก้อน
3. **Claude API batch:** ใช้ `tools/claude_translate.py` เหมาะกับงานจำนวนมาก ราคาถูกกว่าแบบ sync

ทุกวิธีใช้กติกาเดียวกัน:
- `docs/STYLE_GUIDE.md` บอกน้ำเสียง สรรพนาม (ข้า/เจ้า ในบทพูด) และศัพท์ระบบที่ใช้คำอังกฤษ (สกิล, ดาเมจ, บัฟ)
- `docs/AGENT_TRANSLATION_GUIDE.md` บอกวิธีทำงาน ชื่อที่กำหนดตายตัว และรูปแบบพิเศษ (คัมภีร์, กลอน, การเล่นคำ)

### 5.3 ระบบชื่อเฉพาะ (ส่วนที่ยากที่สุด)

เกมนี้มีชื่อเฉพาะหลายหมื่นชื่อ ถ้าไม่คุม คนละก้อนจะแปลชื่อเดียวกันคนละแบบ เราจึงจัดลำดับความสำคัญไว้ดังนี้

1. **`glossary/series_names.tsv`** (`zh  th  variants`) ชนะเสมอ คอลัมน์ variants คือชื่อแบบอื่นที่ห้ามใช้
2. **`glossary/glossary.tsv`** เก็บศัพท์ที่อนุมัติแล้ว
3. **ชื่อที่ใช้บ่อยที่สุดในงานที่แปลเสร็จแล้ว** หาได้ด้วย `tools/name_lookup.py 名1 名2 …`
4. **ถ้าเป็นชื่อใหม่:** ใช้ `tools/translit.py` ถอดเสียงจีนกลางเป็นไทย (ใช้ pypinyin)

กฎตัวอย่าง:
- ชื่อสำนักหรือสถานที่ใช้คำบอกประเภทเป็นไทยแล้วตามด้วยเสียงจีน เช่น สำนักม่อ, หอซิ่วจิน, เขาไต้
- นามสกุลกำหนดตายตัว เช่น 王 = หวัง
- ชื่อดังใช้ชื่อไทยที่คุ้นเคย เช่น ขงเบ้ง, เล่าปี่
- ชื่อทางธรรมให้ถอดเสียง ไม่แปลความหมาย

เมื่อพบว่าชื่อเดียวกันถูกแปลหลายแบบ เราเพิ่มแถวลงใน series_names (ตอนนี้มีหลายร้อยแถว)
แล้วรัน **name pass** ซึ่งไล่แทนที่ชื่อแบบอื่นด้วยชื่อหลัก ทั้งใน DB และในไฟล์ `.out.tsv` ทุกไฟล์
โดยแทนเฉพาะข้อความที่ภาษาจีนมีชื่อนั้นอยู่จริง

### 5.4 Validator (`translate.py check`)

ทุกบรรทัดต้องผ่านเงื่อนไขเหล่านี้ ถ้าไม่ผ่านจะได้ `needs_fix`:
- ไม่มีตัวอักษรจีนหลงเหลือ (ยกเว้นในชื่อ `{placeholder}`)
- ไม่มีตัวอักษรต่างชาติแปลกปลอม เช่น คันจิ/ฮันกึล
- token ทุกตัว (`#X…#E`, `{}`, `%s`, `<LINK>` …) ตรงกับต้นฉบับทั้งชนิดและจำนวน
- ลำดับ `%s/%d` เหมือนเดิม
- จำนวน `\n` และ `|` เท่าต้นฉบับ
- บรรทัด `@en:` ต้องคัดลอกมาตามเดิม

### 5.5 Build (`build_mod.bat`)

0. **`update_game.py check`:** ถ้าเกมอัปเดตแล้ว จะหยุด ป้องกันไม่ให้เอาไฟล์รุ่นเก่าไปทับเกมรุ่นใหม่
1. **`import-queue`:** อ่าน `.out.tsv` ที่ยังไม่ได้ import เข้า DB (สร้าง marker `.imported` กันไม่ให้ import ซ้ำ)
2. **`export-tsv`:** ขยาย `th_new` ของแต่ละข้อความออกไปเป็นทุก key ที่ใช้ข้อความนั้น
3. **`wwmloc.py patch`:** สร้างไฟล์ไทยใหม่จาก `backup/original` แล้ว `verify`
4. **คัดลอกลงโฟลเดอร์เกม:** ถ้าเกมเปิดอยู่จะไม่ทำ

เครื่องมือเสริม:
- `switch_thai.bat` สลับระหว่างมอดกับไทยเดิม
- `restore_original.bat` คืนไฟล์ต้นฉบับ
- `tools/check_installed.py` ตรวจว่าไฟล์ในเกมเป็นของมอดจริง

## 6. เมื่อเกมอัปเดต (`update_game.bat`)

```
update_game.py check   → เทียบ hash ไฟล์ในเกม กับ backup/original และกับ build ล่าสุดของเรา
update_game.py apply   → 1) ย้าย backup เก่าไปเก็บ แล้วสำรองต้นฉบับใหม่
                         2) สำรอง wwm.db
                         3) ผูก key ทุกตัวกับข้อความจีน (ที่อาจเปลี่ยนไป) ใหม่
                            - ข้อความจีนที่เคยแปลแล้ว → ได้คำแปลเดิมทันที
                            - ข้อความจีนใหม่ → status todo (note new:<version>)
                            - ข้อความที่ไม่มี key ใช้แล้ว → unused
translate.py chunks --new → แปลเฉพาะของใหม่ แล้ว build_mod.bat
```

เพราะเราเก็บคำแปลผูกกับ **ข้อความจีน** ไม่ได้ผูกกับ key อัปเดตเกมจึงไม่ทำให้งานที่แปลแล้วหายไป
ตัวอย่างจริง: อัปเดต 2026-11 มีข้อความใหม่ 4,010 ข้อความ ส่วนใหญ่เป็นโหมดหมากรุกออโต้ (江湖弈)
ส่วนอื่นได้คำแปลเดิมกลับมาเองทั้งหมด

## 9. ข้อจำกัดที่รู้อยู่

- **Steam แปลได้ประมาณ 60%:** `_diff` ใน `LocalData/Patch` ถูก patcher ของเกมบังคับคืนต้นฉบับทุกครั้งที่เปิดเกม
  (รายละเอียดในหัวข้อ 2.3) ถ้าอยากได้ครบต้องเล่นผ่าน Launcher แบบ Lite
- **ชื่อที่ยังปนกันบางกลุ่ม:**
  - วัสดุ 珍坯 ยังเรียกหลายแบบ
  - ชื่อรหัสของ 墨门 (燕/鸦/鹤) บางที่ถอดเสียง บางที่แปลความ
  - ค่าตัวหมากในโหมดหมากรุก (N费) เขียนไม่เหมือนกัน
- **คัมภีร์และกลอนโบราณ:** แปลตามความหมายได้ถูก แต่ถ้ามีคนอ่านทวนจะดีขึ้น
  ส่วนที่ subagent แจ้งว่าไม่แน่ใจ ส่วนใหญ่อยู่ในกลุ่มนี้
- **ปริศนาอักษร:** คำตอบที่เป็นตัวอักษรจีนจำเป็นต้องเปลี่ยนเป็นภาษาไทย เพราะ validator ห้ามมีอักษรจีนเหลืออยู่
